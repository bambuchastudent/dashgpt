# Proposal: Zero-DevTools ChatGPT Import Launcher

## Why

Feature 20 made large ChatGPT-history migration resumable, progressive, duplicate-safe and local-first, but the normal launch path still asks the user to paste a generated runner into a browser JavaScript console. That is unacceptable for ordinary users and effectively blocks mobile use because normal iPhone Safari and Android Chrome do not expose the same desktop DevTools flow.

The browser security boundary is real: DashGPT cannot inject arbitrary JavaScript from the DashGPT origin into `chatgpt.com`. The product therefore needs one explicit same-origin browser gesture that a normal user can understand and reuse without installing an extension/plugin or learning developer tooling.

## Product decision

Introduce one reusable **DashGPT Import action**. The user saves it once as a browser-managed action/bookmark and then runs it while on `chatgpt.com`.

Conceptually:

```text
DashGPT
 -> Import ChatGPT history
 -> Save DashGPT Import action once
 -> Open ChatGPT
 -> Run DashGPT Import
 -> receiver opens/handshakes
 -> Feature 20 progressive import continues
```

The product concept is the same on iPhone, Android and desktop. Browser-specific instructions may differ, but there is no separate mobile import architecture.

The action itself is a bounded `javascript:` bookmark action generated by DashGPT from the existing Feature 20 source runner. It executes only when the user explicitly runs it on `https://chatgpt.com`, creates fresh transient session/nonce values, and connects to the current DashGPT origin. If the browser blocks automatic receiver opening, the existing source overlay provides a human `Connect DashGPT` fallback.

## What changes

- Replace the normal DevTools/Console instructions with a reusable `DashGPT Import` browser action.
- Add a compact setup dialog with `Copy import action`, `Open ChatGPT`, and browser-appropriate human instructions.
- Use the same action for first import and resume; the action creates new transient launch IDs every run.
- Keep the Feature 20 imported-card identity, receiver protocol, ACK-after-durable-save behavior, privacy boundary, scheduler and progress-card lifecycle unchanged.
- Keep a truthful fallback state when the current browser cannot execute a saved JavaScript action.
- Preserve current desktop runner copy only as a diagnostic/recovery affordance if needed; it is no longer the normal user path.

## Browser direction

### iPhone / iPad Safari

Use a Safari bookmark/action named `DashGPT Import`. The UI explains one-time bookmark setup in human language. Apple also provides a native `Run JavaScript on Web Page` Shortcuts capability; that remains a compatible future/alternate adapter rather than a separate product model.

### Android Chrome

Use the same saved `DashGPT Import` bookmark action. Chrome Android already surfaces local bookmark suggestions through the omnibox; the UI explains how to run the saved action from the ChatGPT page without referring to developer tools.

### Desktop Safari/Chromium

Use the same saved action from bookmarks/favorites/bookmarks bar. The existing Console runner remains diagnostic fallback only.

## Impact Manifest

### Existing surfaces reused

- `demo/chatgpt-history-import.js` — import-card launcher/progress UI; normal launch behavior changes here.
- `demo/chatgpt-history-source-runner.js` — generated Feature 20 runner; extended with reusable action generation.
- `demo/chatgpt-history-source-runner-core.js` — same-origin source runtime; may receive a narrowly scoped auto-connect option for action launches.
- `demo/chatgpt-history-import-batch.js` — unchanged durable batch receiver/ACK path.
- `demo/vault.js` — unchanged local Vault and deterministic card identity.
- `demo/catalog-bootstrap.js` — unchanged import module lifecycle unless a small launcher integration hook is required.
- `tests/chatgpt-history-import.spec.mjs` and `scripts/verify-chatgpt-history-import.mjs` — extended for action generation/setup/resume contracts.
- Feature 20 OpenSpec remains historical source for import transport/identity; this change supersedes only its normal same-origin execution UX.

### Active overlap

- Issue #44 is the product input for this change.
- Issue #45 owns generic detail-card action leakage and is not absorbed here.
- PR #47 owns the Safari fallback receiver-focus bug and is not absorbed here; this launcher must remain compatible with its eventual merge.
- Scheduler/performance/reindex issues remain separate.

### Privacy/security radius

The action contains only DashGPT receiver origin/path plus generated runtime logic. It must not contain or persist ChatGPT access tokens, cookies, account IDs, authorization headers, session payloads or conversation data. Fresh per-run session/nonce values are generated inside the ChatGPT page and remain transient.

### Tooling

Graphify and Serena are not available through the current ChatGPT/GitHub connector environment. Focused repository/OpenSpec inspection is used instead.

## Non-goals

- Browser extension/plugin/userscript manager requirement.
- Cross-origin injection from DashGPT into ChatGPT.
- Changing the Feature 20 scheduler, batching, storage or imported-card model.
- iCloud Shortcut distribution or Android app packaging.
- Guaranteeing background execution after the ChatGPT source page is closed.
- Fixing unrelated import-card detail actions (#45).
