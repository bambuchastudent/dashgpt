PRIVACY POLICY

Privacy

DashGPT keeps useful AI outcomes as user-controlled Cards. This policy explains what data each supported workflow uses, why it is used, where it goes, how long it remains, and the user controls available.

Data DashGPT handles
Depending on the action you choose, DashGPT may handle distilled Card fields such as title, summary, goal, decisions, facts, constraints, tags, current state, next steps, links, and selected source provenance. Normal Card capture does not require the full raw chat transcript. DashGPT also handles technical request metadata needed to serve the site and MCP endpoint.
Direct Card save from ChatGPT
When you explicitly ask ChatGPT to save or update a Card, ChatGPT/OpenAI distills the current conversation and sends the structured Card fields to DashGPT's upsert_card tool. DashGPT uses those fields only to create or update the requested canonical Card in your authorized Google Drive-backed Vault. DashGPT does not fetch the current ChatGPT conversation or require ChatGPT cookies, session tokens, passwords, or OpenAI API credentials for this write.
OpenAI / ChatGPT
If you use the DashGPT plugin in ChatGPT, OpenAI processes the conversation and the plugin tool call under OpenAI's own terms and privacy practices. DashGPT receives only the tool request sent to its MCP server. DashGPT does not receive a general right to browse your ChatGPT history and does not ask OpenAI for unrelated conversations.
Google Drive authorization
Direct private writes use Google OAuth and request the https://www.googleapis.com/auth/drive.file permission. This lets DashGPT create, discover, read, and update the DashGPT Vault files created or opened through this integration. Google receives the OAuth and Drive API requests required to perform those actions. DashGPT does not request broad read access to all files in your Drive.
Authorization data and retention
The plugin authorization bridge keeps only short-lived authorization state needed to complete OAuth. Pending authorization requests expire after about 10 minutes, one-time authorization codes after about 2 minutes, and DashGPT Card-write bearer grants after at most about 30 minutes and no later than the underlying Google grant. The one-time state may temporarily contain the Google access authorization needed for the exchange. It is not stored in Cards, Vault JSON, tool output, URLs, browser local storage, or intentionally written to application logs. This release does not keep a long-lived Google refresh token for plugin writes.
User-owned Card retention
Canonical private Cards remain in the user's selected DashGPT Vault until the user updates or removes them or deletes that Vault. For the first direct-write provider, the Vault is stored in the user's Google Drive. DashGPT does not copy those Cards into a separate hosted Card database as part of the plugin authorization flow.
Local Vault
When DashGPT is used without a connected remote provider, locally created or imported Cards are stored in a portable DashGPT Vault in the browser. They remain until you clear or replace that browser data. Clearing browser storage can remove the local copy, so exporting or intentionally syncing a Vault is recommended when the data matters.
GitHub Vault sync
If you explicitly connect a GitHub repository or folder, DashGPT uses the authorized GitHub App installation to synchronize Vault objects. During installation you choose which repositories the app may access. DashGPT requests repository Contents read/write access because it needs to read and commit Vault files. Short-lived GitHub installation authorization is used server-side and is not placed in the browser Vault, Card content, Context Pack, or chat.
GitHub connection state
The browser receives a signed HttpOnly session cookie identifying the selected repository/path and GitHub App installation. Disconnecting GitHub clears the DashGPT session; it does not silently delete your local Vault or remote repository files.
Published Cards and public catalogs
An instance operator may intentionally publish Card-compatible legacy Results and saved Dashes with the site. Published content and the public DashGPT instance protocol can be visible to anyone who can access that site. Public MCP read tools can read only content intentionally exposed by the selected compatible instance; they cannot read a private browser or Google Drive Vault merely because the plugin is installed.
Remote DashGPT instances
When you give DashGPT another HTTPS DashGPT site URL, the public plugin gateway may contact that site to verify compatibility and read the published Cards/Results, Dashes, or Context Packs you requested. That site's operator controls its hosting and server logs.
ChatGPT shared links
If you explicitly provide a public ChatGPT Share URL to a Share-ingestion workflow, the DashGPT server may fetch that public conversation to create a Card-compatible result. Direct Card save does not depend on Share retrieval. Do not create or provide a public Share link for material you do not intend to expose through that link.
Explicit import fallback
The prepare_result_import fallback computes a portable payload and an explicit Open in DashGPT link. Calling it does not write the Card to a Vault. Persistence happens only after the user completes the browser import.
Recipients and infrastructure
Data is sent only to services needed for the workflow you invoke: the DashGPT hosting environment receives MCP/site requests; Google receives OAuth and Drive requests when Google Drive is connected; GitHub receives repository API requests when GitHub sync is connected; and a user-selected remote DashGPT instance receives requests when you explicitly use it. The production demo currently runs on Cloudflare Workers, whose infrastructure processes requests needed to operate the service. DashGPT does not sell Card content or use it for advertising.
Data minimization
Raw chat transcripts are not part of normal Vault synchronization or direct Card save. DashGPT stores distilled Cards and explicitly selected provenance. Passwords, API keys, provider tokens, payment data, private keys, and authentication credentials should not be stored in Cards; direct-save validation rejects common credential-like patterns.
User controls
You decide when a Card is saved: direct writes require an explicit save/update request. You can edit or delete Cards in your Vault, delete the DashGPT Vault file from Google Drive, disconnect provider access, clear browser-local DashGPT data, or stop using the plugin. Public content remains public only while the operator continues to publish it. Removing provider access may stop future synchronization or writes but does not automatically erase files already stored in that provider.
Self-hosting
When DashGPT is self-hosted, the person or organization operating that instance controls its hosting configuration, logs, access policy, backups, secrets, published content, and any retention beyond the application-level rules described above.

DashGPT is experimental. This policy is updated when supported data flows materially change.
